# Justgame — Codex 인수인계

작성: 2026-10-18 (한국 시간)

이 문서는 ChatGPT에서 진행하던 게임 개발을 Codex에서 이어가기 위한 프로젝트 요약이다. 전체 대화 기록이나 플레이어 개인 저장 파일은 포함하지 않는다. 구현 사실의 기준은 현재 저장소의 소스와 테스트다.

## 레벨업 폭죽·제작대 변경 (구현 2026-10-19, 배포 요청 2026-10-22, 한국 시간)

레벨업 폭죽과 제작대 건설·안내를 추가했다. 빌드 및 전체 67개 테스트를 통과했고, Chromium에서 건설·비용 차감·폭죽·장착·재접속과 모바일 화면을 확인했다. 사용자가 GitHub를 통한 Cloudflare 배포를 요청했다. 이번 빌드 식별자는 `justgame-fireworks-workbench-20261022-v34`이며, 배포 결과는 해당 커밋의 `Workers Builds: game` 검사와 운영 `/health`의 `build` 값으로 확인한다. 아래 시작 지점의 커밋·배포·검증 기록은 이전 배포 기준이다. 상위 장비 제작법은 계속 미구현이다.

## 사용자가 원하는 게임

우주선을 타고 행성을 탐험하며 자원을 채집하고, 집과 기지를 건설하고, 새로운 생명체와 만나는 한국어 2D 게임이다. 장기적으로 ARK처럼 레벨이 오르면 더 좋은 장비를 제작하고 우주선을 강화해 다음 행성에 진입하는 성장 흐름을 원한다.

레벨, 우주선 강화 키와 인벤토리는 구현·배포했다. 이어 받은 요청에 따라 레벨업 폭죽과 제작대 건설을 로컬에 추가했다. 상위 장비 제작은 아직 구현하지 않았다. 다음 작업 요청이 없다면 구현 완료와 예정 사항을 구분해서 설명한다.

## 현재 성장 규칙

`game/core.js`의 `MAX_LEVEL`, `XP_REWARDS`, `SHIP_TIERS`, `PLANET_TIERS`, `levelProgress`를 기준으로 한다.

| 활동 | 경험치 |
| --- | --- |
| 자원 지점 완전 채집 | 12 |
| 새 생명체 발견 | 25 |
| 해당 생명체와 첫 교류 | 15 |
| 건물 건설 성공 | 35 |
| 유적 첫 조사 | 60 |
| 새 행성 착륙 완료 | 80 |
| 루미의 탐사기 복구 완료 | 120 |

레벨업마다 폭죽과 레벨 문구를 표시한다. 여러 레벨을 한 번에 얻으면 각 레벨을 순서대로 축하하며, 화면 효과 비활성/강도 0에서는 폭죽을 생략한다. 저장 불러오기나 훈련으로는 축하를 재생하지 않는다.

Lv.2에는 누적 100 XP가 필요하다. 다음 단계 요구량은 50씩 증가한다. 반복 스캔·대화·재방문으로 중복 보상을 받지 않으며, 훈련은 본게임 경험치를 지급하지 않는다.

| 우주선 | 요구 레벨 | 강화 비용 (철광석 / 수정 / 식물) | 새 항로 | 비행 속도 | 워프 연료 |
| --- | --- | --- | --- | --- | --- |
| MK I | 1 | 기본 | 베르단트·솔라라 | 1.00배 | 18 |
| MK II | 3 | 24 / 8 / 10 | 닉스 | 1.15배 | 16 |
| MK III | 6 | 48 / 16 / 16 | 엠버 | 1.30배 | 14 |
| MK IV | 10 | 84 / 32 / 24 | 프리즈마 | 1.50배 | 12 |

- 강화는 착륙 상태로 우주선 가까이에서 순차 실행한다. 레벨·재료·거리·진행 중인 연출과 예상 강화 단계를 검증한다.
- 재료는 강화 성공 시 한 번 차감한다.
- 미해금 행성은 워프와 직접 착륙 모두 제한한다. 훈련 비행에는 항로 제한이 없다.
- 이전에 방문한 행성 접근은 유지한다.
- I 인벤토리는 보유 재료와 세 가지 기본 도구를 보여주며 보유 도구를 장착할 수 있다.
- 제작대 건설은 구현했다. B에서 철광석 16 · 수정 4 · 식물 8로 배치하며, 기존 건물과 동일하게 저장하고 건설 성공 시 35 XP를 지급한다. E로 안내와 인벤토리를 열 수 있다. 상위 도구 제작, 제작대 업그레이드와 장비 등급 시스템은 미구현이다.

## 자원과 환경

- 화면 이름은 **식물**이다. 이전 이름 바이오매스/풀로 되돌리지 않는다. 내부 저장 키 `biomass`는 호환성을 위해 유지한다.
- 식물 노드와 식물 선물은 본게임 베르단트 전용이다. 훈련에서는 별도 실습 재료가 있다.
- 곡괭이 → 철광석, 도끼 → 식물, 칼 → 수정. 소유·장착 검증과 타격 시점 판정을 유지한다.
- 자원 재생은 게임 시간 150초 기준이며 메뉴로 정지한 시간에는 진행하지 않는다.
- 노드 ID와 다른 노드 위치를 보존하도록 결정적 월드 생성 후 식물 노드를 필터링한다.
- 지상 속도는 베르단트 기준 중력에 반비례한다. 베르단트 1.00, 솔라라 1.25, 닉스 약 1.43, 엠버 약 0.77, 프리즈마 약 1.67배.
- 각 행성 기온/중력은 게임 환경 설정값이다. 실제 행성 자료가 아니다.

## 루미의 탐사기 복구 임무

- 본게임 베르단트에 루미와 탐사기가 있다. 훈련 교관/시스템과 구분한다.
- 탐험 일지에서 시작하며 탐사기 과부하·안테나 고장 장면을 보여준다.
- 철광석 18, 식물 10, 수정 4로 탐사기 근처에서 수리한다.
- 상태: `available → malfunction → collecting → repairing → complete`.
- 고장과 수리 연출은 건너뛰기 및 저장 후 재개를 지원한다.
- 수리 시작 때 한 번 비용을 차감한다. 완료 후 솔라라의 별빛 기록석 신호를 표시한다.
- 임무를 완료하지 않아도 기본 우주선으로 솔라라에 갈 수 있다.

- 플레이어 저장은 브라우저에 있다. GitHub 저장소를 Codex에 연결하는 것은 개인 플레이 저장을 옮기는 작업이 아니다.

## 작업·검증·배포

1. `AGENTS.md`와 `README.md`를 읽고 원격 최신 코드와 로컬 변경을 확인한다.
2. 관련 원본 파일을 수정한다. 생성물만 수정하지 않는다.
3. `npm run build`, `npm test`를 실행한다. UI는 가능한 환경에서 실제 조작으로 확인한다.
4. 게임 규칙이 바뀌면 `site.js`의 해당 가이드와 README를 함께 맞춘다.
5. 배포 요청에 따라 GitHub에 반영한다. `main`은 Cloudflare 자동 배포와 연결돼 있다.
6. 배포 작업에서는 Workers Builds 결과 및 실제 화면을 확인하고 정확히 보고한다.

핵심 테스트: `test/progression.test.mjs`, `workbench.test.mjs`, `ship.test.mjs`, `tools-flight.test.mjs`, `tutorial.test.mjs`, `probe.test.mjs`, `grass.test.mjs`, `gravity.test.mjs`, `motion.test.mjs`, `site.test.mjs`.

현재 Cloudflare 설정은 `wrangler.jsonc`와 `worker.js`에 있다. 새 호스팅/저장소를 만들 필요는 없다. 로컬 또는 Codex 환경에서 새로 로그인하거나 별도 연동이 필요한 경우 기존 연결 상태를 확인한 뒤 안내한다. 인증 정보를 소스에 넣지 않는다.

## 이후 확장 후보 (미구현)

사용자의 큰 방향에 맞는 다음 후보는 레벨별 제작법 해금과 상위 도구 제작이다. 별도 요청을 받으면 현재 인벤토리와 성장 규칙에 연결한다. 장비 효율·재료·해금 레벨을 실제 게임 보상과 함께 설계하고, 표시만 있는 제작 버튼을 만들지 않는다. 새 생명체와 건축 확장도 장기 목표다.
